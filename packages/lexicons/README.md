# @homeward/lexicons

Lexicon schemas for Homeward's public records, plus TypeScript types and validators generated by [`@atproto/lex`](https://www.npmjs.com/package/@atproto/lex).

> **Namespace:** `pet.homeward.*` assumes we control `homeward.pet`. No production records until the domain is secured (#11).

## Records

| NSID                           | Key    | Purpose                                                                          |
| ------------------------------ | ------ | -------------------------------------------------------------------------------- |
| `pet.homeward.org.profile`     | `self` | Rescue organisation profile. Its presence marks the account as an org.           |
| `pet.homeward.animal`          | `tid`  | One animal. Never holds identification numbers (those are private, #17).         |
| `pet.homeward.listing`         | `tid`  | 1..n animals offered together (`bonded`), with status, criteria and fee.         |
| `pet.homeward.adopter.profile` | `self` | Optional, deliberately coarse public adopter profile. Household data is private. |

`pet.homeward.defs` holds shared types: `place` (town-level, coarse coordinates), `area` (country/region only), `species`, `size`, `ageGroup`, `image` (alt text required) and `money` (minor units).

## Design notes

- **Criteria are an open union** of typed objects (`#childrenCriterion`, `#gardenCriterion` and so on), each with a `level` of `required` or `preferred`. Validation is precise, and new criterion types can be added without breaking existing records or readers.
- **Listings reference animals by AT URI, not strongRef**, so editing an animal (e.g. adding photos) doesn't orphan the listing.
- **No floats in Lexicon**, so coordinates are decimal strings, rounded to 2 places (about 1 km) before publishing.
- **Drafts are never published.** Only listings meant to be public become records.
- **Enumerations use `knownValues`, not `enum`**, so values can be added later; readers treat unknown values conservatively.
- `com.atproto.repo.strongRef` is vendored by hand because lexicon DNS resolution isn't available in every build environment.

## Changing a schema

1. Edit the JSON in `lexicons/`.
2. Run `pnpm --filter @homeward/lexicons lex:build`.
3. Commit the JSON and `src/generated` together. CI fails if they drift.

Published records live in people's repositories indefinitely, so changes must stay backwards compatible: add optional fields, never rename or remove fields, and never tighten constraints.
